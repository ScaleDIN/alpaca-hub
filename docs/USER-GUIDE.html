Alpaca Hub

One ASCOM Alpaca service for every astronomy device on this PC. Imaging programs that speak Alpaca find all of them at one address. Each device has a tab with its status and controls, also on a phone.

What gets installed

  • The hub (AlpacaHub-<version>-Setup.exe): finds devices on the serial ports and USB, serves them over Alpaca, and shows the status page. It has no device drivers of its own.
  • A driver for each kind of device (AlpacaHub-<driver>-<version>-Setup.exe), for example wcover (WandererCover V4-EC flat panel), wbox (WandererBox Plus V3), nitecrawler (Moonlite NiteCrawler), optec (Optec Gemini / Hercules, FocusLynx / ThirdLynx), zwoeaf (ZWO EAF focuser) and zwoefw (ZWO EFW filter wheel). Install the hub first, then the drivers you need, in any order, while the hub runs or not.

Drivers go to %ProgramData%\AlpacaHub\drivers. Each driver runs in its own process: if one fails, the hub starts it again and the other devices carry on.

No ASCOM Platform needed. The hub and its drivers work on their own: Alpaca programs talk to the hub over the network, not through Windows' ASCOM drivers. Only a program that knows classic ASCOM but not Alpaca needs the ASCOM Platform (see Alpaca programs).

Before the first start

If this PC ran the older services (the NiteCrawler Alpaca service or WBPlus Stock Alpaca): stop and uninstall them first. Only one program can use a COM port.
Settings are taken over once. On its first start the hub copies the older services' settings (focus maximum, dew settings, names) into its own folder, %LOCALAPPDATA%\alpaca-hub. Check them on each device's tab before moving anything: focus maximum on the NiteCrawler tab, and the dew heater settings on the box's tab.

WandererBox: the box stores every command it receives. With the older service's dew settings, the first start may send it a dew command (for example manual 100 %), and a box set to "switch the dew heater off on exit" gets a command when the hub stops. Look at the dew settings you used before, and change them on the box tab if needed.

Starting and stopping

Start menu → Alpaca Hubstarts the hub and opens its status page (or just opens the page if it already runs)
Start menu → Stop Alpaca Hubstops it cleanly: each driver stops its device first
Start at logonan installer option (off unless ticked)
Desktop shortcutsan installer option (off unless ticked): Alpaca Hub and Stop Alpaca Hub on the desktop, the same as in the Start menu
Start menu → Settings and log folder%LOCALAPPDATA%\alpaca-hub: hub.json, hub.log, drivers\<driver>\<unit>.json (each device's settings), logs\<driver>.log (each driver's log)

The status page is at http://localhost:11111/. The firewall option lets phones and Alpaca programs on other computers in your home network reach it; the page shows the address to use (and a QR code).

Who can use the devices? Windows calls each network either Private (your home network, one you trust) or Public (a café, a hotel, anywhere else). On a Private network, phones and other computers can use the devices through the hub. On a Public network nobody else can, not even your own laptop on the same Wi-Fi; programs on this PC still can. To share the devices, set this PC's network to Private (Windows Settings → Network & internet → your connection → Network profile type).

Windows Firewall may ask on the first start ("Do you want to allow public and private networks to access this app?"). It asks when the network is set to Public. Don't allow Public networks: that would let anyone on that network use your devices. Set the network to Private instead. Pressing Cancel can make Windows block the hub for other computers; if they still can't reach it once the network is Private, Start menu → Allow network access (firewall) undoes it.

The Overview tab

  • Devices: each device found, with its port, a short status and its Alpaca numbers. Click one to open its tab. Rename gives a device a name of your own, shown on its tab, its card and in Saved history (leave it empty for the usual name). Without one, a name stored in the device itself is shown, such as the custom ID set with ZWO's software.
  • The tabs keep the same order whatever COM port each device is on. Drag a tab to move it, or press Ctrl+Shift+←/→ on it; the hub keeps that order for every browser, and an unplugged device's tab comes back in its place. Reset order under the devices puts them back in the usual order.
  • Two or more of a kind (two filter wheels, say): each keeps its tab name ("ZWO EFW #2") and its Alpaca number for good, also while it's unplugged, so a new one gets the next number. When one is gone for good: Renumber tabs on its driver's card numbers the tabs 1, 2, 3 again, and Renumber Alpaca numbers under the devices numbers the Alpaca numbers 0, 1, 2 per kind. The second shows what changes and asks first: an imaging program that chose a device by its number (Focuser #1) must choose it again. Neither works while an imaging program is connected to the devices concerned.
  • Scan now: looks at the serial ports at once (the hub does it every 15 s anyway).
  • Drivers: every driver with its version and state (running, restarting, failed, off, refused). Turn off stops a driver and frees its ports until you turn it on again. A driver that failed several times shows its last log lines and Try again. A newer version that waits for programs to disconnect shows Switch now.
  • The chart of everything and Saved history: every device's readings on one time axis, and each device's 1-minute averages saved to a file per day (kept 1 to 365 days, one setting for all), listed by device name with Download and Open folder.
  • Serial ports (fold it open): every COM port and what the hub made of it. Ignore keeps the hub away from a port for good, for example a meter's USB cable or a device another program uses: never opened, never probed, also after a restart. A port whose USB chip has a serial number stays ignored on any COM number. Stop ignoring undoes it.
  • Updates: a line at the top when there is a new version, and the setting at the bottom (see Updates).

ZWO focusers and filter wheels

  • The EAF and EFW are reached through ZWO's own software library (included with their drivers), on USB. Settings stored in them (maximum step, reverse, backlash, one-way rotation, their custom ID) are set with ZWO's own drivers or tools; the hub only reads them.
  • A filter wheel's filter names and focus offsets are set on its tab and kept in the hub for that wheel, so every imaging program sees the same ones.
  • Don't use ZWO's own ASCOM driver at the same time: it can open a focuser or wheel the hub already holds, and then two programs move it. The hub's tab says "moved by another program" when that happens.

Alpaca programs

Choose the devices from the Alpaca discovery list (or enter this PC's address and port 11111). Each device keeps its Alpaca number and UniqueID, so profiles stay valid. While a program is connected, a device's tab locks its controls; Unlock lets you change things deliberately.

Programs that speak Alpaca (NINA, SharpCap, ConformU and others) need nothing else. A program that only knows classic ASCOM drivers needs the ASCOM Platform (6.5 or later) on the PC where that program runs: in the ASCOM Chooser, turn on Alpaca discovery and pick the hub's device, and the Platform makes it look like an ordinary ASCOM driver to the program.

Updates

Once a day (and about a minute after it starts, if the last look was a day ago) the hub reads the list of published versions online. When there is a newer hub, or a newer version of a driver installed here, a line at the top of the Overview says so; open it to see what's new in each.

  • What it sends: one request for the list, with nothing in it but the hub's version number. No device, computer or user details.
  • Turning it off: untick Check for updates online at the bottom of the Overview. The hub then sends nothing at all. Check now looks straight away.
  • Install (on the hub's PC only): the hub downloads the installer, checks it against the published list (its size and SHA-256) and runs it; Windows asks for administrator rights. A file that doesn't match is deleted, never run. Downloads go into %LOCALAPPDATA%\alpaca-hub\updates, which is emptied the next time the hub starts or downloads another update. On a phone or another PC the Overview shows the updates but installs nothing.
  • A driver update takes over by itself within seconds if no program is connected to that driver's devices; otherwise when they disconnect, or when you press Switch now under Drivers. The devices keep their tabs, Alpaca numbers and UniqueIDs.
  • A hub update stops the hub, updates it and starts it again; the page reloads when it's back. Connected programs lose their devices for about a minute, so Install asks first. When both are new, install the hub first: a driver that needs a newer hub says so and has no Install button until then.
  • By hand: download the installers from the project's releases page and run them, hub first. Settings, device numbers and history are kept.

Removing

  • A driver: Windows Settings → Apps → "Alpaca Hub driver: …". The hub stops the driver and frees its ports.
  • The hub: Windows Settings → Apps → "Alpaca Hub". Removing the hub leaves the drivers installed.

When something doesn't work

  • Every scan is slow, or a port is "stuck": if it's a port you don't need the hub for, Ignore it under Overview → Serial ports.
  • A device isn't found: is another program (an older service, a vendor's tool) using its port? Close it and press Scan now. Is the device's driver installed and running (Overview → Drivers)?
  • "stuck inside Windows' serial driver": some USB serial chips hang when opened. The hub keeps going with the other ports; unplugging the device's USB cable and plugging it back in frees it.
  • Phones or other computers can't reach the hub: is this PC's network set to Private (Windows Settings → Network & internet)? If you pressed Cancel at the firewall question, or left the firewall option unticked when installing: Start menu → Allow network access (firewall). It asks for administrator rights, removes the rules that block the hub and allows it on private networks again (never on public ones).
  • A driver keeps restarting or failed: Overview shows why and its last log lines; the full log is logs\<driver>.log in the settings folder.
  • A ZWO focuser or filter wheel answers slowly (moves start late, Halt takes a second or more): is it on the same USB hub as a USB serial adapter that is in use (an FTDI chip, such as the Optec Gemini's)? Move it to another USB port or hub.
  • Two boxes or panels: these have no serial number, so the hub tells them apart by their USB socket. Keep each on its own socket.
